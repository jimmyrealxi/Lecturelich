## 0. บทบาทและวิธีทำงาน

เธอคือคู่หูพัฒนาแอปของฉัน ฉันเรียน IT ปี 1 เทอม 2 (จบ ปวส. มา เรียนต่อ 2 ปี) เคยทำแอป **LabHub** มาแล้ว ทั้ง repo `parnppk/ProJect_LabHub` (โฟลเดอร์ `iot-lab-management/`) ใช้ stack เดียวกับโปรเจกต์นี้ ก่อนเริ่ม **ให้ clone มาอ่านเป็นตัวอย่าง** โดยเฉพาะ `CLAUDE.md`, `docs/rules/app.md`, `docs/rules/supabase.md`, `docs/DEPLOY_PWA.md`, `lib/web/webPush.ts`, `public/sw.js`, Edge Function `send-push` และ trigger `notifications_push` ให้ยืมแพตเทิร์นมาใช้ ห้ามคัดลอกโค้ดเรื่องยืม-คืนหรือห้องคอมมาใส่

**กติกาการทำงาน (ใช้ตลอดโปรเจกต์)**
- ตอบภาษาไทยเสมอ สั้น ประหยัด token ทำช้าแต่รอบคอบ และเช็ก edge case เองก่อนส่ง
- งาน UI ทุกอย่าง: **ทำ mockup HTML ให้ฉันดูก่อน** พอฉันโอเคแล้วค่อยเขียนโค้ดจริง
- **ไม่ commit/push เองถ้าฉันไม่สั่ง** ฉัน commit ผ่าน GitHub Desktop ให้เตรียมข้อความไว้ให้: Summary บรรทัดเดียว และ Description เป็น bullet ภาษาไทย
- ห้าม commit ลง main ให้ทำงานบน branch
- ไม่เปิดเบราว์เซอร์หรือ dev server ถ้าฉันไม่สั่ง
- **ทำทีละขั้น** จบแต่ละขั้นแล้วหยุดรอให้ฉันทดสอบและอนุมัติก่อนทำขั้นต่อไป
- ถ้ามีเรื่องที่ต้องตัดสินใจ หรือข้อมูลไม่พอ ให้ถามก่อนเดา
- migration ใหม่ทุกไฟล์ต้องมี RLS policy ในไฟล์เดียวกัน และให้ฉันเป็นคนรันใน Supabase SQL Editor เอง

## 1. แอปนี้คืออะไร

**StudyQuest** คือ PWA ผู้ช่วยเรียนส่วนตัว ใช้บนมือถือแบบเร็ว ๆ ไม่เกิน 10 วินาที ส่วนงานหนัก เช่นอ่านสไลด์และทำงาน ทำบนคอมที่บ้าน แอปไม่ได้แทนเครื่องมืออื่น แต่ทำหน้าที่**บอก เตือน จด และลิงก์ไปหา** Google Classroom, กลุ่มไลน์ และ NotebookLM ของแต่ละวิชา และมี**ระบบ progression แบบเกม**ที่ทำให้อยากเปิดแอปและอยากเรียน

**ผู้ใช้:** ฉันกับเพื่อนหรือน้องที่เรียนวิชาเดียวกัน มือถือปนกันทั้ง iPhone และ Android ใช้บนคอมผ่านเบราว์เซอร์ด้วย

**ปัญหาที่ต้องแก้**
1. จำตารางเรียนไม่ได้ ไม่รู้ว่าวันนี้เรียนอะไร
2. งานมาจากหลายทาง ทั้ง Classroom ในคาบ และไลน์ จึงลืมส่งหรือส่งช้า
3. ไม่รู้ว่าแต่ละคาบเรียนอะไรไป พอสอบเลยไม่รู้ว่าต้องอ่านอะไร
4. **ปัญหาหลัก:** ช่วงสอบไม่รู้จะโฟกัสอะไร และอ่านแล้วจำไม่ได้
5. ไม่รู้ว่าแต่ละวิชาได้คะแนนไปเท่าไหร่แล้ว และขาดเรียนไปกี่ครั้ง

## 2. ฟีเจอร์ทั้งหมด

**หลัก: ข้อมูลส่วนตัวเป็นค่าเริ่มต้น แชร์ได้แค่ "งานและกำหนดส่ง"**

| ฟีเจอร์ | รายละเอียด | ส่วนตัว / แชร์ |
|---|---|---|
| หน้าวันนี้ | คาบวันนี้ (วิชา เวลา ห้อง) คาบที่กำลังเรียนหรือคาบถัดไป งานใกล้ส่ง การ์ด "คาบนี้จบแล้ว ยังไม่ได้จด" และปุ่มเช็กชื่อเร็ว | ส่วนตัว |
| ตารางเรียน | วิชา วันในสัปดาห์ เวลาเริ่ม-จบ ห้อง ซ้ำเหมือนกันทุกสัปดาห์ (วิชาเดียวมีได้หลายช่วง) และวันเปิด-ปิดเทอม | ส่วนตัว |
| หน้าวิชา | ไทม์ไลน์โน้ตทุกคาบ งานของวิชา คะแนน การเข้าเรียน และปุ่มลิงก์ Classroom / ไลน์ / NotebookLM | ส่วนตัว |
| จดหลังคาบ | ข้อความสั้น ถ่ายรูปกระดาน (ย่อรูปก่อนอัปโหลด) เพิ่มหัวข้อที่เรียน กด ⭐ หัวข้อที่ "อาจารย์บอกว่าออกสอบ" และเพิ่มงานได้ในหน้าเดียว | ส่วนตัว |
| เช็กชื่อ | มาเรียน / ขาด / ไม่มีเรียน นับครั้งที่ขาด และเตือนเมื่อใกล้เกณฑ์ (ค่าเริ่มต้นต้องเข้า 80% แก้ได้) ถ้าไม่มีเรียนจะไม่นับและไม่เตือนให้จด | ส่วนตัว |
| คะแนนและเกรด | สัดส่วนคะแนนต่อวิชา (เช่น เก็บ 30 กลางภาค 30 ปลายภาค 40) กรอกคะแนนที่ได้ เกณฑ์ตัดเกรดแก้ได้ (ค่าเริ่มต้น A 80, B+ 75, B 70, C+ 65, C 60, D+ 55, D 50) และคำนวณว่า **"ปลายภาคต้องได้อย่างน้อยเท่าไหร่ถึงได้เกรดเป้าหมาย"** | ส่วนตัว |
| งานและกำหนดส่ง | ชื่องาน วิชา กำหนดส่ง แหล่งที่มา (Classroom / ในคาบ / ไลน์) และลิงก์ ถ้าอยู่ในห้องร่วม ทุกคนเห็นงานเดียวกัน | **แชร์** (สถานะ "ส่งแล้ว" และคะแนนเป็นของส่วนตัว) |
| ห้องร่วม | สร้างห้อง แล้วชวนเพื่อนด้วยโค้ดหรือลิงก์ ใช้แชร์งานอย่างเดียว | แชร์ |
| แจ้งเตือน | push หลังเลิกคาบตามเวลาในตาราง (ชวนให้จด) และก่อนถึงกำหนดส่งงาน | ส่วนตัว |
| ระบบเกม | XP เลเวล passive tree ของวิชา บอสสอบ และตัวละครพิกเซล (ดูข้อ 4) | ส่วนตัว |

## 3. เทคโนโลยีและข้อกำหนด

- **หน้าบ้าน:** Expo + expo-router + TypeScript ทำเป็น PWA (เว็บเป็นหลัก) โฮสต์บน Vercel ใช้ Expo SDK เวอร์ชันเสถียรล่าสุด เช็กก่อนเริ่ม
- **หลังบ้าน:** Supabase (Auth, Postgres, Storage, Edge Functions, pg_cron) **สร้างโปรเจกต์ที่ region สิงคโปร์ (ap-southeast-1)**
- **ล็อกอิน:** Google เหมือน LabHub
- **ข้อมูลฝั่งแอป:** TanStack Query เก็บแคชลงเครื่อง เพื่อให้เปิดแอปแล้วเห็นข้อมูลทันที
- **Push:** ยืมแพตเทิร์นจาก LabHub ทั้งหมด คือ `push_subscriptions` และตาราง `notifications` → trigger (pg_net) → Edge Function `send-push` (VAPID)
- **ตั้งเวลา:** pg_cron เช็กทุก 1–5 นาทีว่ามีคาบไหนเลิก หรือมีงานไหนใกล้ครบกำหนด แล้วเพิ่มแถวลง `notifications` (ระวัง Disk IO บนแพ็กเกจฟรี)
- **เวลา:** ทุกอย่างอิง Asia/Bangkok
- **ภาษา UI:** ไทยทั้งหมด
- **ข้อจำกัดของ iPhone:** ต้อง "เพิ่มไปยังหน้าจอโฮม" ก่อนถึงจะรับ push ได้ ให้มีหน้าแนะนำการติดตั้งในแอป และปุ่มขออนุญาตแจ้งเตือนต้องมาจากการกดของผู้ใช้

**หลักด้าน performance (วางตั้งแต่วันแรก)**
- Optimistic UI กับทุกการกดที่ใช้บ่อย เช่นเช็กชื่อ ติ๊กส่งงาน บันทึกโน้ต และ +XP ให้หน้าจอเปลี่ยนทันที แล้วค่อยซิงก์เบื้องหลัง ถ้าล้มเหลวค่อยย้อนกลับ
- โชว์ข้อมูลจากแคชก่อน แล้วค่อยอัปเดต ใช้ skeleton แทนวงกลมหมุน
- ให้ฐานข้อมูลคำนวณ XP เลเวล เลือดบอส และคะแนนรวม ผ่าน view หรือ RPC แล้วส่งกลับมาแค่ตัวเลข และ select เฉพาะคอลัมน์ที่ใช้
- ย่อรูปฝั่งเครื่องก่อนอัปโหลด และมีรูปย่อสำหรับรายการ
- แอนิเมชันใช้ `transform` กับ `opacity` เท่านั้น
- service worker เก็บไฟล์แอปไว้ และโหลดหน้าแยกตามที่เปิด
- วัดด้วย Lighthouse ก่อนและหลังแก้

## 4. ระบบเกม (progression)

**แรงบันดาลใจ:** หน้าใช้งานได้แรงบันดาลใจจากสีชุดใน Fallout ส่วนระบบเกมได้แรงบันดาลใจจาก Path of Exile 2 ทั้งหมดนำเสนอเป็น**ภาพพิกเซล 2D** หยิบมา**แค่บรรยากาศและระบบ ห้ามใช้ภาพ ไอคอน ชื่อ ฟอนต์ หรือโลโก้ของทั้งสองเกม** ภาพทั้งหมดต้องวาดเองหรือใช้แพ็กที่ license อนุญาตให้ใช้ในแอป

**หลัก:** ให้รางวัลเฉพาะสิ่งที่ช่วยให้เรียนดีขึ้นจริง ห้ามให้ XP แค่เพราะเปิดแอป ห้ามมี streak ที่ขาดแล้วรีเซ็ต และระบบเกมต้องไม่บังหน้าที่หลักของแอป

**XP (ต่อวิชา มีเพดานต่อวันกันปั๊ม XP)**

| การกระทำ | XP |
|---|---|
| มาเรียน (เช็กชื่อ) | 5 |
| จดหลังคาบ | 10 (+5 ถ้ามีรูป) |
| ส่งงานก่อนกำหนด 1 วันขึ้นไป | 20 |
| ส่งงานตรงเวลา | 10 |
| ตอบคำถามทวนถูก / ทวนหัวข้อ | 3 ต่อครั้ง สูงสุด 30 ต่อวัน |
| อ่านครบรอบ "เริ่ม 5 นาที" | 5 |

ค่าเหล่านี้เก็บเป็น config ที่แก้ได้ง่าย ไม่ฝังไว้ในโค้ดหลายจุด

**เลเวล**
- เลเวลวิชา: XP ที่ต้องใช้ขึ้นเลเวลถัดไป = 50 × เลเวลปัจจุบัน
- เลเวลตัวละครหลัก คิดจาก XP รวมทุกวิชาตลอดทุกเทอม
- **เทอม = ซีซั่น:** เลเวลวิชาเริ่มใหม่ทุกเทอม ส่วนตัวละครหลักไม่รีเซ็ต จบเทอมมีการ์ดสรุปซีซั่น เช่นจดไปกี่คาบ ส่งงานตรงเวลากี่ % และเกรดเทียบกับเป้า

**Passive tree ของแต่ละวิชา**
- หัวข้อแต่ละหัวข้อเป็นโหนดหนึ่งจุด เรียงตามลำดับคาบ หัวข้อ ⭐ เป็นโหนดใหญ่ (notable)
- โหนดสว่างเมื่อทวนแล้ว และค่อย ๆ จางลงถ้าไม่ได้ทวนตามรอบ

**บอสสอบ**
- กลางภาคและปลายภาคของแต่ละวิชาเป็นบอสหนึ่งตัว พร้อมนับถอยหลังวันสอบ
- เลือดบอส = จำนวนหัวข้อในช่วงที่ออกสอบ หัวข้อ ⭐ มีน้ำหนักมากกว่าปกติ
- ทวนหัวข้อไหน บอสก็เสียเลือดเท่านั้น **ถ้าหัวข้อที่ทวนแล้วไม่ได้ทวนซ้ำตามรอบ (1, 3, 7, 14 วัน) บอสจะฟื้นเลือดคืน** ซึ่งก็คือการทวนแบบเว้นระยะ
- แสดงเป็นเกจ "พร้อมสอบ %" และรายการหัวข้อที่ยังขาด เรียง ⭐ ไว้ก่อน

**สีความหายาก:** ขาวคือปกติ ฟ้าคือ magic เหลืองคือ rare และส้มคือ unique ใช้กับรางวัล ความสำเร็จ และหัวข้อที่ทวนครบรอบ

**ตัวละครพิกเซล:** sprite 32×32 เปลี่ยนชุดทุก 5 เลเวล ราว 5 ระดับ ช่วงแรกใช้ภาพ placeholder ไปก่อน

**ความรู้สึกตอนใช้:** +XP เด้งเป็นตัวเลขพิกเซล แถบ XP ขยับให้เห็น และเลเวลอัปมีแอนิเมชันสั้นไม่เกิน 1 วินาที

## 6. ร่างฐานข้อมูล (ปรับได้ แต่ถามก่อนถ้าเปลี่ยนโครงใหญ่)

ทุกตารางส่วนตัวมี `user_id` และ RLS `user_id = auth.uid()`

- `profiles` — ชื่อ รูป ตั้งค่า (เกณฑ์ขาดเรียน เวลาเตือน)
- `terms` — ชื่อเทอม วันเปิด-ปิด และ `is_current`
- `subjects` — term_id รหัสวิชา ชื่อ สี ลิงก์ Classroom / ไลน์ / NotebookLM เกณฑ์ตัดเกรด (jsonb) และเกรดเป้าหมาย
- `class_slots` — subject_id วันในสัปดาห์ เวลาเริ่ม-จบ ห้อง (ซ้ำทุกสัปดาห์)
  - **คาบแต่ละวันคำนวณจาก slots กับช่วงเทอม ไม่ต้องสร้างแถวล่วงหน้า** เก็บแถวเฉพาะเมื่อมีข้อมูล (เช็กชื่อ โน้ต)
- `attendance` — subject_id, date, slot_id, status (`present | absent | no_class`)
- `class_notes` — subject_id, date, slot_id, text, photo paths
- `topics` — subject_id, note_id, title, `is_starred`, exam (`midterm | final`), `review_stage`, `last_reviewed_at`, `next_review_at`
- `exams` — subject_id, kind, date (ใช้กับบอส)
- `grade_components` — subject_id ชื่อ น้ำหนัก (%) คะแนนเต็ม
- `scores` — component_id, assignment_id (null ได้), คะแนนที่ได้, เต็ม
- `rooms`, `room_members` — ห้องร่วมกับโค้ดชวน
- `assignments` — **แชร์ได้:** room_id (null = ส่วนตัว), subject ref, title, due_at, source, link, created_by
  - RLS: เห็นได้ถ้าเป็นเจ้าของ หรือเป็นสมาชิกห้อง
  - เรื่องใครแก้งานได้บ้าง ค่าเริ่มต้นให้เฉพาะคนสร้างกับเจ้าของห้อง (ถามฉันก่อนสรุป)
- `assignment_status` — **ส่วนตัว:** user_id, assignment_id, done, submitted_at
- `xp_events` — user_id, subject_id, action, xp, ref_id, created_at (มี unique กันได้ XP ซ้ำจากการกระทำเดียวกัน)
- view / RPC: XP และเลเวลต่อวิชา เลเวลตัวละคร เลือดบอสและพร้อมสอบ % คะแนนรวม และคะแนนที่ต้องได้ปลายภาค
- `push_subscriptions`, `notifications` — ตามแบบ LabHub

**การจับคู่วิชาข้ามคนในห้องร่วม:** งานในห้องผูกกับ "วิชาของห้อง" (รหัสวิชา) แต่ละคนจับคู่เข้ากับ subject ของตัวเองด้วยรหัสวิชา
